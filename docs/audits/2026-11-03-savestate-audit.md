# Save-state reliability audit (iCube#58, R7 code-level part)

Date: 2026-11-03. Base: origin/develop 49b114f18c. Method: code reading only. No build, no test run, no device.
Scope: every save/load/delete/auto-save/auto-resume path in the iCube app plus `Source/Core/Core/State.cpp`.
Labels used below: **PROVEN** = follows from the cited code; **DEVICE** = needs a device check; **NOT DETERMINED** = could not be settled from code in this repo.

Paths are relative to `Source/iOS/App/Common/` unless they start with `Source/Core`. `Swift/` files are under `Swift/`.

## 0. Mechanics every entry point shares

| Fact | Evidence |
|---|---|
| File name = `{StateSaves}/{GameID}.s{NN}` for numbered slots (`NN` zero padded, 1...UINT32_MAX accepted by the bridge, UI uses 1-10 and 99 for Continuity). Resume state = `{GameID}.auto`. Quick-save history = `{GameID}.quick-{UUID}.s01`. Sidecars append `.json` and `.png` to the full state name. | `Emulation/TVEmulationBridge.mm:466-474` (slot), `:484-495` (auto), `Swift/QuickSaveHistoryPersistence.swift:23` (history), `Swift/SaveStateMetadataStore.swift:23-25` (sidecar) |
| The game id in the file name is `SConfig::GetGameID()` at the instant of the call, read under `CPUThreadGuard` for the checked save paths. | `TVEmulationBridge.mm:398-405` |
| Every checked UI path carries a (gameID, session identifier) pair. The session id is bumped synchronously on every core `Starting`/`Stopping`/`Uninitialized` transition, so a same-title reboot is a different session. | `TVEmulationBridge.mm:97-107` |
| Core write path: serialize on the CPU thread into a buffer, hand to the "Savestate Worker" thread, write `{file}{N}.tmp`, close, hard-link the old file to `{tmp}.previous`, `rename(tmp, dest)`, `rename(previous, lastState.sav)`. The current file is never moved aside; a failed write/close/rename removes the temp and leaves the old file. | `Source/Core/Core/State.cpp:401-509`, `Source/Core/Core/StateFileTransaction.h`, unit tests `Source/UnitTests/Core/StateFileTransactionTest.cpp` |
| Core read path: header game id (first 6 chars) must equal the running game, cookie version must equal `STATE_VERSION` (193), extended header version must be 1, LZ4 blocks must decode to exactly `uncompressed_size`, `DoState` markers must match. Before touching the file the core snapshots the live machine into `s_undo_load_buffer`; a `DoState` failure calls `UndoLoadState`. | `State.cpp:790-835` (`ValidateHeaders`), `:837-902`, `:904-968` |
| `lastState.sav` (the "undo save" file) is one file for ALL games and is never listed by the app. | `State.cpp:467`, `Swift/FilesystemSaveStateProvider.swift:149-152` |
| The app never calls `UndoLoadState`/`UndoSaveState`/`LoadLastSaved`/`SaveFirstSaved`. There is no user-visible undo for a load or an overwrite. | grep of `Source/iOS`: the only `State::` callers are in `TVEmulationBridge.mm` (`SaveAsWithResult`, `SaveAsAndWait`, `Load`, `LoadAs`, `LoadAsAndWait`) |
| Serialized app-side save queue: `SaveStateService.saveQueue` (serial, userInitiated). All completed-snapshot saves, the quit paths and history saves run on it. The core call it makes (`State::SaveAsWithResult`) hops onto the CPU thread itself; the queue thread then blocks on the future (`completion.get()`), not the main thread. | `Swift/SaveStateService.swift:13`, `TVEmulationBridge.mm:416-418` |

## 3. Findings, ranked by data-loss risk

| ID | Sev. | Finding | Evidence | Action taken here |
|---|---|---|---|---|
| F1 | High | **"Resume where I left off" only saves at a clean Quit.** Backgrounding, jetsam, swipe-away, crash or low battery produce no auto-state. The next launch resumes the state from the last Quit (or nothing), losing all progress since. `willTerminate` calls `Core::Stop` and `Config::Save` only. The code comment claiming "every quit path is covered" (`SaveStateService.swift:337-339`) is false for system termination. | `Services/DolphinCoreService.mm:299-337`; no other `autoStateFilePath`/`saveStateToPath` caller (grep); `TVEmulationBridge.mm:162-173, 200-239` | None (needs a design decision: save `.auto` on `didEnterBackground` under a background-task assertion, or reword the setting) |
| F2 | High | **Save & Quit silently overwrites the selected quick slot.** The compat overload carries `allowOverwrite: YES` and no consent; S3/S4 ask, S6 does not. | `SaveStateService.swift:142-180`, `TVEmulationBridge.mm:387`, `PauseMenuView.swift:599, 1046`, `EmulationScreen.swift:1183-1185` | None (product decision: confirm, or save to a history file instead) |
| F3 | High | **Programmatic stops discard unsaved progress with weak or no consent.** `GameLaunchRequest` (Top Shelf, play URL) stops a running game with no prompt; with resume off nothing is saved, with resume on a failed auto-save is only `NSLog`'d and the stop proceeds. `stop()` also blocks its caller (main) on the worker. | `Swift/GameLaunchRequest.swift:15-22`, `TVEmulationBridge.mm:162-173`, `Swift/TVLibraryView.swift:2358-2362` | None |
| F4 | Medium | **Sidecar failure turns a committed save into a reported failure.** The slot file is already replaced; the old sidecar (title, time, play time) now describes the new bytes; quit path shows the retry alert and a Retry rewrites it again. | `SaveStateService.swift:158-180` | None (private, bridge-bound; fix = treat sidecar failure as a warning, return the snapshot) |
| F5 | Medium | **Rejected loads are reported as "Game isn't ready to load yet"** (truncated, corrupt, wrong game, netplay), so the user is told to wait instead of that the state is bad. | `QuickSaveActions.swift:117, 182`; `QuickSaveMenuRoutingTests.swift:160-174` encoded it | **Fixed** (commit after this one): new `.loadFailed` outcome, "Couldn't load save state" |
| F6 | Medium | **Delete/rename failures are invisible, and the tvOS pane deletes with one press.** The iOS/tvOS filmstrip confirms; `TVSaveSlotsPane` does not. A tvOS user can remove the only copy of a state (and `.auto` "Continue") without undo. | `SaveStatesViewModel.swift:64-66, 73-75`; `TVSaveSlotsPane.swift:274-284, 326` | None |
| F7 | Medium | **No game-revision/mod identity in the state.** Same-ID different disc revision, vanilla vs modded boot and mod A vs mod B share `{GameID}.sNN`; a load succeeds and runs on mismatched memory. ## 4. Proposed device checklist (owner)

Run on iPhone, iPad and Apple TV where marked; keep one build for the whole run.

1. Save in slot 1 at a recognizable point, advance, Load: game state and paused/running state match (paused menu stays paused). Repeat for slots 2 and 10, then quit, relaunch, Load.
2. Overwrite an occupied slot from the picker and the tvOS pane (expect a prompt), then **Save & Quit with an occupied quick slot** (F2: expect it to overwrite without asking).
3. Overwrite a slot after sitting in the pause menu for more than a minute: does the thumbnail match the new state (F9)?
4. With Resume on: play, press Home, then swipe the app away (and separately, kill it from Xcode). Relaunch: confirm the resume point is the last Quit, not the last moment (F1).
5. Top Shelf / play-URL launch of another game while one is running, Resume on and off: is progress kept (F3)?
6. Truncate a slot with `devicectl device copy` (cut the file to half) and Load it: note the toast, the core alert and that the game is unchanged. Repeat with a flipped byte near the end (silent corruption, F10) and with a zero-byte file.
7. Fill the device storage (< 50 MB free), then Save and Save & Quit: expect a visible failure and the previous state intact. Free space and confirm the old state still loads.
8. Kill the app with the debugger during a large Wii save (several attempts); relaunch and check the slot loads, and `StateSaves` for leftover `*.tmp*` files (F11).
9. Build bump check: load a state written by the previous TestFlight build; expect "incompatible" in the list and verify what happens to `.auto` after the next Quit (F8).
10. Boot a modded disc and a vanilla disc of the same game ID, save a manual slot in one, load it in the other (F7).
11. tvOS: delete a slot from the Save Slots pane, then from the filmstrip: compare confirmations (F6).
12. Two devices with iCloud sync: save on A, let it sync, load on B (compatible build); check the 5-second same-instant conflict and the Apple TV purge recovery from R3.
13. Netplay and RetroAchievements hardcore: Quick Load should say it failed, not "not ready".
14. Time Save and Load on the slowest supported device (Wii title): the main-thread stall on Replace Game / play-URL stop (S8) should stay far below the watchdog limit.

## 5. What could not be determined from code

- How `PanicAlertFmt` / `MsgAlert` ("Could not read state data", "State header corrupted") is presented on iOS and tvOS, and whether answering it can block or crash (`docs/handoff-2026-09-28-hang-fixes-verification.md` test 7 is the nearest evidence). It decides what a user sees on a truncated file.
- Real main-thread stall of `TVEmulationBridge.stop()` (S8) with a large state.
- Whether APFS can surface a zero-length destination after power loss without `fsync`.
- Apple TV purge recovery: the PVCloudSync/PVSyncRules/PVContinuity sources were read from the sibling checkouts in `ReleaseWork/` at the pinned 1.0.2 (`PVSyncRules`), not from this repo's resolved package versions, so behavior of the resolved build may differ.
- Whether the scanner can upload a state while the quit-time worker is still flushing (the sync gate and `Core::Stop` flush suggest not).
- Other save paths in the core that are not state files (memory cards, Wii NAND saves) are out of scope.
