# Physical DEV play-controls smoke harness

Prepared 2026-10-20. **Not run on a device.** `PhysicalPlayControlsSmokeTests.swift` passes Swift frontend parsing only. No SDK build, installation, launch, device action, or production session access was performed to prepare it.

The bundle identifier is fixed to `com.joemattiello.iCube-debug`. Production `com.joemattiello.iCube` and its paused Sonic session must remain untouched. The harness activates an already running DEV session; it skips if DEV is not running and has no library/game launch fallback. DEV's disposable Luigi/NSMB session may briefly resume to expose the toolbar. Successful checks leave the pause menu open; failure cleanup attempts the same and records its final accessibility tree/screenshot. Inspect that attachment if cleanup cannot confirm pause.

## Operator preflight and execution

1. Prepare the current DEV build and disposable real-game session using the existing authorized device workflow. Confirm the game/session is disposable, Confirm on Stop is enabled, quick-save mode is history, boot is unmodded, and there are fewer than ten unkept history saves. Do not change production or existing classic/kept states.
2. Select full-screen landscape iPad, width at least 1000 points and standard Dynamic Type. Set `ICUBE_PLAY_CONTROLS_WIDE_PREFLIGHT=enabled`; geometry and wide Audio availability are checked at runtime. Compact portrait, Split View and accessibility-size toolbars skip this audit, rather than being reported as product failures. Add this standalone file to the generated physical UI test harness (project generation/SDK execution is owned by the coordinating agent). Pass `ICUBE_PLAY_CONTROLS_PREFLIGHT=enabled` into the **test runner process environment**, not just the target app's launch environment. Do not run unrelated tests.
3. `testToolbarMuteRestoresVolumeAndHistoryUI` checks the toolbar accessibility labels, hit targets of at least 44×44 points (0.001-point AX rounding tolerance), Mute making Volume's AX value `0%`, unmute restoring its exact original positive integer percentage, and the history browser's selected mode and Save new state label. Start with a nonzero configured volume. No save/load is pressed in this test. Original volume is captured into teardown state before the first mute tap. Cleanup checks that value even after an abrupt failed assertion; on any mismatch (zero or an incorrect positive value), it adjusts the native slider to the original percentage and verifies restoration. It then attempts Pause independently before reporting cleanup failures. It does not trust Mute to restore an incorrect remembered level.
4. Optional write/load check: pass `ICUBE_HISTORY_SAVE_PREFLIGHT=enabled` and `ICUBE_HISTORY_EXISTING_BASENAMES` as a JSON array containing **all existing quick-history basenames for the active DEV game, including kept saves**, e.g. `[]` only if confirmed empty. Keep the preflight current; no other writer should create history during this run. `testOneNewHistorySaveAndExplicitLoadSameCard` opens Saves, asserts history is already selected and the exact action is Save new state, presses it once, finds exactly one immutable `.quick-UUID.s01` card absent from the inventory, selects that exact card, checks selection, and presses Load selected once. There is no retry or classic-mode fallback. Inventory prevents lazy offscreen cards being mistaken for the new save. The new state intentionally remains afterward.
5. Review the xcresult's retained numbered screenshot and accessibility-tree attachments. Record device/OS, tested build and source revision, preflight inventory/count, observed new filename and save/load outcome. Confirm DEV is paused and production's session remains untouched through the preflight/owner workflow.

## Limits and stop conditions

- Missing preflight gates skip checks. Missing/covered targets, unavailable history, classic Save to slot labels, multiple new identities, unexpected alerts or failed load dismissal fail the test. Never continue by pressing Quit, Save & Quit, Reset, Delete, classic Save, overwrite confirmation, Keep, or Quick Load.
- The UI harness establishes visible control behavior and explicit load request/dismissal, not file byte integrity, no-pruning proof, core restoration fidelity, crash freedom over time, or actual speaker/headphone audibility. Root's container preflight/postflight and owner listening check supply those separate observations.
- Source gives Volume a label and value but no stable identifier. This harness uses the native slider's `Volume` label. English labels are intentional; unexpected localization fails instead of choosing another action.
- The optional save test intentionally changes the disposable DEV emulation state by loading its own newly created state. It never loads existing classic/history/kept saves. No save is removed.
- Native iPad popover dismissal uses the known on-screen toolbar Pause center outside the audio popover. If native modality marks that background button unhittable, only its center coordinate is permitted for dismissal; exposed popover bounds must exclude that point. Both normal flow and teardown verify Volume disappears before normal Pause interaction. Runtime coverage/layout must still be established on the physical device; unexpected geometry fails cleanup. Cleanup is best effort and its final assertion/attachments are required evidence.
